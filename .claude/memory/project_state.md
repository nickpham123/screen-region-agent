## Built and working

- `mistral_vision_query.py` — Python reference implementation of the **single-turn** vision call, `ask_about_region(image_path, question) -> str`, calls Mistral's `mistral-small-latest`. Note: the actual contract needed now is multi-turn (`askAboutRegion(imagePath, conversationHistory)`, see decisions.md) — this file is reference for the core request logic, the JS port needs to extend it to carry conversation history, not just translate it 1:1.
- Electron app scaffold (`main.js`, `index.html`, `package.json`) — main process creates one `BrowserWindow` (`contextIsolation: true`, `nodeIntegration: false`), loads `index.html`. Verified: `npm start` launches the app and shows the window.
- `globalShortcut` hotkey listener — accelerator is **`Control+1`**, chosen after testing seven candidates hands-on (11/11 activations, zero failures). Unregisters on activation and re-registers on finalize. The main process sends the trigger key's code to the overlay on activation, so the accelerator and the renderer's keyup check can't drift apart. **Usability note**: the modifier must be pressed slightly before the trigger key — macOS only matches a global accelerator when the modifier is already down.
- Selection Overlay (`overlay.html`, `overlay.js`, `preload.js`) — transparent frameless full-screen `BrowserWindow` **repositioned to whichever display holds the cursor at activation** (single window, moved per-activation; not one overlay per display). Marked `setVisibleOnAllWorkspaces` so it can take keyboard focus on a secondary display's Space. Multi-monitor behavior verified 2026-08-21 on built-in Retina + external QHD, including the disambiguating case (cursor on one display, focused window on the other, no click) — the overlay follows the cursor. Takes focus on activation, shows a "Release to select" badge, draws a freeform cursor trail on a canvas while the key is held, accumulates a bounding box (computed, not rendered), and finalizes on the trigger key's release. Includes click-to-reset (clears the trail mid-gesture with a flash cue), minimum-size validation, and screen-edge clamping. Drawing discards the synthetic activation mousemove and anchors on the next real one, so no phantom trail is drawn and a selection begins where drawing actually started. Verified across repeated runs: deliberate holds (including 8-20s), fast taps, and press-while-still-moving all behave correctly.
- Stuck-gesture safety net, now a **liveness watchdog** — the renderer forwards the held trigger key's auto-repeat `keydown`s as a `gesture-alive` ping, re-arming a 5s main-process timer. It therefore fires on 5s of *silence*, never on gesture length, so an active hold can't be truncated at any duration; a genuinely stuck gesture is still force-closed with both processes reset (renderer state cancelled via IPC, overlay hidden, hotkey re-registered). Replaced a fixed 5s deadline that was cutting off real in-progress holds. Degrades to the old behavior if macOS key repeat is set to Off.
- Single-instance lock (`app.requestSingleInstanceLock()`, acquired before `app.whenReady()`) — a second launch exits before creating a window or registering the accelerator, logging the `pkill` recovery command; the primary logs the blocked attempt and shows no UI. Guards a confirmed failure mode where concurrent instances all registered the same accelerator and fought over focus. Tested by deliberate double-launch. Marked in code as the hook where Step 5 should focus the Chat Panel instead.
- Screen Capture (`capture.js`, plus additions to `preload.js`/`overlay.js`/`main.js`) — `captureRegion(bbox, displayId) -> {cropPath, fullPath}`, implemented 2026-08-22. Standalone diagnostic (`diagnostics/verify_capture_*.js`) confirmed on real hardware that the scaleFactor conversion formula, `getUserMedia` constraints, and `desktopCapturer` source↔display mapping all hold; also caught a real bug (`track.getSettings()` returns stale dimensions on a session's second capture — fixed by reading `video.videoWidth/videoHeight` instead). Screen Recording permission checked via `systemPreferences.getMediaAccessStatus('screen')`, fails loud if not granted (no pre-prompt onboarding UI built yet — deferred, tracked in todo.md). **Crop correctness verified with real gestures on both displays** (2026-08-22) — bbox-to-pixel cross-checks matched exactly, including an exact multi-line text match on the external QHD display. No trail/badge/reset-flash contamination observed. This was Step 4's highest-risk item and it's now closed on both displays. Writes into `temp/screen-region-captures/` (a dedicated subfolder, not the OS temp root — see the Chat Panel row below), changed 2026-08-22 to match the temp-file-lifecycle design.
- **Chat Panel — window lifecycle, temp-file lifecycle invariant, hold-to-talk key mechanics, and text field + message history all implemented and hands-on verified; only real voice recording/transcription remains** (`main.js`, `chatPanel.html`, `chatPanelPreload.js`) — window lifecycle + temp-file invariant implemented 2026-08-22; hold-to-talk mechanics and text/history both implemented and verified 2026-08-23. `createChatPanelWindow(cropPath, fullPath, displayId)` opens a fresh `BrowserWindow` per session (never reused; closed, not hidden, on session end — see decisions.md for why this was chosen over reusing one window like the overlay), centered on the capture's display, marked `setVisibleOnAllWorkspaces` for the same secondary-display-Space reason as the overlay. The accelerator stays *registered* throughout the session (revised from an initial unregister-for-the-session design after review — see decisions.md); its callback now branches three ways on a second `Control+1` press: panel not open → normal region-selection gesture; panel open but not focused → focus the existing panel; **panel open and focused → hold-to-talk** — `Digit1` is claimed by the accelerator here too (confirmed empirically, not assumed — see decisions.md's chord-timing findings), so this path unregisters, sends `'hold-to-talk-start'` for the renderer to bootstrap its held-state from (never a local `keydown`), arms a dedicated liveness watchdog, and ends strictly on the renderer's real `Digit1` `keyup`, never a timeout. `#input` (auto-focused) submits a `{role:'user', content}` turn on Enter, rendered into `#history` and sent via `chatPanelAPI.submitTurn()` to the already-scoped `chat-turn-added` listener. On the panel's `closed` event, `endChatSession()` enforces decisions.md's temp-file invariant: zero turns → delete the temp crop/full files; ≥1 turn → move them into `userData/captures/` via `moveFile()` (rename, falls back to copy+unlink on `EXDEV`); if the window closes mid-hold, the watchdog is cleared and the hotkey re-registered immediately rather than waiting it out. **Not yet built**: real voice recording/transcription (backend now `nodejs-whisper`, evaluated and confirmed working 2026-08-23 — see below; not yet wired into the two `TODO(next slice)` points in `chatPanel.html`) — and Step 8's real `logConversation()` write, which the "keep" branch currently stands in for with a console log and a `TODO(Step 8)`. **Hands-on verified 2026-08-23** across three separate sessions: (1) on both the built-in and an external Dell monitor, 4 real gestures — panel opened and visibly took keyboard focus every time; re-pressing `Control+1` while open (3 presses) correctly focused the existing panel; every close correctly discarded (0 turns), confirmed both via the log and directly on disk. (2) hold-to-talk: 3 real hold cycles (~3.1s, ~8s, ~2.2s) in one session, every one showing clean start → no watchdog force-close (the 8s hold in particular only survives if the liveness pings are genuinely re-arming the watchdog, not by luck) → end by real keyup → clean re-registration, confirmed by a normal gesture working immediately after. (3) text/history: 3 real turns typed and submitted in one session — **this was also the first time the "keep" branch of `endChatSession()` ever fired end-to-end**, closing a gap tracked since earlier the same day (previously only `diagnostics/verify_move_file.js`'s standalone unit test covered `moveFile()`). Confirmed on disk, not just the log: files present in `userData/captures/` at byte-identical sizes to temp (content survived the move intact), temp folder empty afterward (genuine move), crop image opened cleanly with real, legible content. This closes Step 5's window-lifecycle/temp-file-lifecycle/hold-to-talk-mechanics/text-history slice.
- **Voice transcription backend evaluated: `nodejs-whisper`, replacing `whisper-node-addon`** — `whisper-node-addon`'s published `darwin-arm64` binary was confirmed broken (a `dlopen` failure on its own `libwhisper.1.dylib`, traced to a CI-machine-specific rpath baked into the build, not fixable via standard `DYLD_LIBRARY_PATH` workarounds — see decisions.md). `nodejs-whisper` evaluated instead (the broken package's own README-recommended alternative): shells out to a compiled `whisper-cli` subprocess rather than an in-process native addon (sidesteps the Electron-ABI question entirely), compiles whisper.cpp from source on first use (needs `cmake`, installed via `brew install cmake`) rather than shipping a prebuilt binary. Both properties that justified the original backend choice re-verified empirically via a real build + real transcription (`diagnostics/verify_nodejswhisper.js`), not assumed to carry over: on-device (only the one-time model download touched the network), and Metal acceleration genuinely engaged at runtime (`ggml_metal_device_init: GPU name: MTL0 (Apple M1 Pro)`, `whisper_backend_init_gpu: using MTL0 backend`) — confirmed real GPU use, not just ARM64 compatibility. Also measured: near-exact transcription accuracy and 775ms inference time once built. `whisper-node-addon` uninstalled (also cleared an `npm audit` critical finding to zero — confirmed attributable solely to it). `nodejs-whisper` is now the sole dependency beyond `electron`.
- **Voice recording — implemented and hands-on verified 2026-08-23.** `chatPanel.html` captures raw PCM via a `ScriptProcessorNode` while `holding`, hands it to `main.js` on the real keyup; `main.js` builds a 16kHz WAV by hand (no `ffmpeg` dependency — see the row above), applies a duration guard keyed on actual captured audio length (not hold time), calls `nodewhisper()`, sends the transcript back to populate `#input`. Distinct visible feedback for mic-unavailable/too-short/transcription-error, never a silent nothing. `extractTranscriptText()`'s string-vs-array ambiguity resolved empirically before relying on it (confirmed: always a plain string in practice, despite the package's own `.d.ts` claiming otherwise). **Verified hands-on across two sessions, 5 real dictations**: 16kHz sample rate honored exactly (no resampling needed), transcriptions accurate, all ended by real keyup. Two real issues surfaced by testing and fixed: multiple dictations were replacing instead of accumulating (fixed — now appends); the field was a single-line input that only showed the tail of a growing message (fixed — switched to an auto-growing `<textarea>`, `Shift+Enter` for a literal newline). Re-verified after both fixes, confirmed working by the user. Full evidence trail in decisions.md. **This closes Step 5's core loop**: window lifecycle, temp-file invariant, hold-to-talk key mechanics, text/history, and voice are all built and hands-on verified.

## Known unreliable

- **Releasing the hotkey within ~445ms** loses the gesture — deterministic, not intermittent. `globalShortcut` consumes the trigger key's original keydown, so the overlay is blind to the key until macOS auto-repeat starts (~445ms measured); a key the window never saw yields no keyup either. Bounded to ~2.5s by the initial-liveness deadline. Fully explained — see decisions.md's consolidated hold/release section §1.
- ~~Focus instability on activation~~ — **retracted 2026-08-21**, was an artifact of multiple Electron instances competing for the accelerator and focus during testing. Confirmed directly: one keypress logged by five separate instances within 2ms. Clean single-instance measurement: `isFocused` `true` on 32 of 33 gestures, vs `false` on 6 of 8 contaminated. See decisions.md §4.
- **Selection overlay is deaf whenever the hotkey is unregistered.** The accelerator comes off for the whole duration of a gesture including a hung one, so hotkey presses during that window do nothing. Now bounded to ~2.5s rather than 5s, but not eliminated.

## Architecture summary

Single-process Electron desktop app (main + renderer processes) today. Only external network dependency is the Mistral API call. No backend, no database — Phase 1–6 storage is local-only (SQLite/JSONL on the user's own machine). Phase 7 (if/when there are real users) adds Supabase (Postgres + Auth + Storage + Edge Functions) as the backend — explicitly not being built yet.

## Known gaps / risks

- No real usage data exists yet, so the data pipeline and fine-tuning phases are entirely unvalidated in practice
- Electron code exists for Steps 1-3 (scaffold, hotkey, selection overlay), all merged to `main`. **Steps 4-8 (capture/crop, Chat Panel, vision call, wiring, logging) are still unbuilt** despite the amount of design work done — don't mistake detailed docs for built code.
- Step 3 took far more debugging than its scope suggested, almost entirely in OS-level input behavior rather than app logic. Expect Step 4 to have its own version of this: it triggers macOS's Screen Recording permission and must map overlay coordinates onto two displays with different scale factors.
